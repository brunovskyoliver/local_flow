# Latency: this Mac against the server (2026-10-01)

A partial record toward T095 (quickstart §5). It covers dictation and rewrite latency and the network path only. T095 stays open: meeting finalization, upload bytes, the second-user wait and the memory rows were not measured here.

## Conditions

- Client: MacBook, Mac17,2, Apple M5, macOS 27.0 (26A428), about 30 minutes after a reboot. Spotlight was still indexing (one process at about one core); the 1-minute load average was 2–4 during the runs.
- Server: Mac mini, M5 Pro, 24 GB, macOS 27.0, install `283ebe6` (see [server-install.md](server-install.md)).
- Network: the address the app uses, `https://mac-mini.tailf15b6.ts.net`. It resolved to the tailnet address `100.74.87.3`, routed through the owner's WireGuard tunnel (`utun9`) over an iPhone hotspot (`172.20.10.0/28`). Tailscale itself was stopped on the MacBook, and Funnel was not in the path. The replay's conditions file says `home-wifi-via-tailscale-funnel`; that label was wrong.
- Model on both sides: Qwen 3.5 4B MTPLX Optimized Speed, with the launcher's flags (`localflow-mtplx`).

## Network path

20 HTTPS requests to `/v1/remote/identity` from the MacBook:

| | Median | p95 | Min |
| --- | --- | --- | --- |
| TCP connect | 61.8 ms | 80.2 ms | 51.8 ms |
| TLS done | 150.9 ms | 165.1 ms | 127.5 ms |
| Total | 217.7 ms | 244.6 ms | 190.5 ms |

An ICMP ping to `100.74.87.3` averaged 64.6 ms, so most of this is the hotspot and the tunnel. The app keeps its channel open, so a new connection's cost is paid once, not per request. Funnel was turned off later the same day (ADR 0028 amendment); the app's path did not change.

## Dictation

`scripts/remote-dictation-benchmark.sh --runs 1` in a Debug build of the production app, with 10 recordings (`sk-01`…`sk-05`, `en-01`…`en-05` from `build/speech-fixtures/`), fed in real time. The figure is the time from key release to the final text. Medians and p95 come from the app's report.

| Path | Boost off: median / p95 | Boost on: median / p95 |
| --- | --- | --- |
| Server | 303 / 614 ms | 295 / 1,200 ms |
| This Mac (Parakeet) | 200 / 240 ms | 311 / 377 ms |
| Server unreachable, local fallback | 189 / 332 ms | 199 / 329 ms |

- The server adds a median 103 ms with boosting off and none with it on (−15 ms). The p95 is higher on the server: three of 20 remote rows took over 600 ms (`sk-04` 614 and 1,200 ms, `en-04` 654 ms).
- No remote row failed. Every fallback row failed fast as `unreachable` and finished locally.
- Transcripts matched between server and local except `sk-03`, with boosting off and on.
- Ten recordings and one run are a small sample: the p95 is the second-slowest of ten.

## Rewriting

### Same corpus on both machines

`scripts/rewrite-quality.py fixtures/rewrite/corpus-v1.json`, 40 items × 3 modes, sent to flowd on loopback on each machine. This is the model and flowd only, with no network or channel in front of them. Total median / p95, and the backend's first-token median:

| Mode | Server, short | This Mac, short | Server, ordinary | This Mac, ordinary |
| --- | --- | --- | --- | --- |
| clean | 281 / 395 ms (168) | 452 / 648 ms (254) | 417 / 526 ms (178) | 630 / 811 ms (268) |
| polished | 299 / 395 ms (150) | 482 / 610 ms (219) | 463 / 637 ms (198) | 747 / 1,059 ms (263) |
| concise | 277 / 395 ms (150) | 427 / 615 ms (222) | 491 / 636 ms (176) | 749 / 1,036 ms (262) |

Short is 29 items and ordinary 10 per mode; one item per mode is unmeasured by the script. Every mode kept all 40 protected entities on both machines, with no hard failure. On this Mac, MTPLX was started for the run (ready about 8 s after start) and its first request is included.

### Real use, end to end

Succeeded rows of `rewrite_attempts` in this Mac's history database, read-only. The time runs from the request to the last byte, as the app recorded it. "Short" means input under 120 characters.

| Origin | Rows | Short: median / p95 | Ordinary: median / p95 | Total minus backend (median) |
| --- | --- | --- | --- | --- |
| This Mac, `127.0.0.1:8080`, 2026-09-17…10-01 | 673 + 495 | 747 / 1,409 ms | 1,246 / 3,087 ms | 38–47 ms |
| Server over the channel, 2026-10-01 | 25 + 17 | 708 / 1,335 ms | 862 / 1,573 ms | 116–124 ms |

These rows mix modes, input lengths and, for the local rows, two weeks in which the local setup may have changed. The server rows are from one day. Use them as a cross-check of the corpus run, not as a controlled result.

## What this says

- Rewriting is faster on the server. Its model step takes 62–66% of this Mac's time. With the channel's roughly 120 ms added, the server is ahead by about 30–65 ms for short text and about 90–165 ms for ordinary text, depending on the mode. The real-use rows point the same way.
- Dictation is about 100 ms slower on the server with boosting off and the same with it on, with a longer tail. Local Parakeet on the M5 is already fast, and the server mainly saves this Mac from holding the model.

## Found while measuring

- **Check connection** timed a real connection only on its first press. The ping parked its channel at op 1, and the next press reused it without a network round trip, which explains the "Answered in 3 ms" in Settings. `RemoteChannelPool.roundTrip` now closes any parked channel, opens a new one, times it to `ready` and closes it. `testARoundTripAlwaysOpensAFreshChannel` covers it.
- `scripts/remote-dictation-benchmark.sh` built the result path as `$PWD/$outdir`, so an absolute `--output` sent the app's report to a folder that did not exist, and the run was lost. Its summary also failed on rows without a `failure` key. Both are fixed.
