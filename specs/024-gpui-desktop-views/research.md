# Research: Feature 024

## R1 Tracking and mixed-style headlines
GPUI has no letter spacing, and flex children can't wrap mixed italic and roman text as one paragraph. `flow_ui::Txt` is a custom element: it shapes with `text_system().layout_line`, adds the tracking to each glyph position, wraps at word boundaries itself and paints through the public `Window::paint_glyph`. No GPUI patch. Kerning from the shaper is kept. Plain text with no tracking uses the same element.

## R2 Accessibility
Only elements with an id and a role reach AccessKit, and plain strings and Kit `Label` have neither. `Txt` always has both: its `a11y_role` is `Label`, `write_a11y_info` sets the value, and its id hashes the caller's source location and the text, so loops don't produce duplicate ids. A boundary check rejects bare strings in page code. AccessKit's Mac adapter fills on a frame rendered after activation (Phase 0), so the AX dump triggers a redraw.

## R3 Fonts
GPUI ignores variable font weights, so `flow-ui` embeds static instances generated by fonttools from the bundled OFL fonts, as in the spike.

## R4 Icons
SF Symbols can't ship on Windows. `flow-ui` maps each symbol name to a bundled Lucide SVG (ISC). A visible change, approved in the plan.

## R5 Data
The Swift migrator in `HistoryMigrations.swift` is the schema's source. `flow-core` opens that database with `rusqlite` and doesn't migrate. Test and audit databases come from the Swift migrator, filled with synthetic content.

## R6 Preferences
The Swift app uses `UserDefaults`. Until cutover the Rust app keeps the same key names in a JSON file in its data root. Importing the real domain is Feature 028.

## R7 Headless tests
`gpui_kit::test` renders real views in a test window and can find, click and type. It doesn't check pixels, so looks are covered by the screenshot audit.
